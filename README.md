# OkypBot - Telegram Bot для интеграции с Okdesk CRM

Telegram бот для автоматизации работы с системой Okdesk CRM. Бот позволяет пользователям регистрироваться, создавать заявки и отслеживать их статус прямо из Telegram с поддержкой двусторонней интеграции через webhooks и автоматической классификацией заявок с помощью ML.

## 🚀 Основные возможности

### Базовые функции
- **Регистрация пользователей**: Поддержка физических и юридических лиц
- **Интеграция с Okdesk**: Автоматическое создание контактов и компаний
- **Создание заявок**: Создание заявок в Okdesk через Telegram
- **🔥 Webhook интеграция**: Получение уведомлений о комментариях, изменениях статуса и назначениях
- **🔥 Двусторонняя связь**: Обмен сообщениями между клиентами и специалистами
- **Отслеживание статуса**: Мониторинг статуса заявок в реальном времени
- **Поиск по ИНН**: Автоматический поиск компаний по ИНН
- **Привязка к компаниям**: Автоматическая привязка сотрудников к компаниям
- **Просмотр заявок**: Просмотр списка заявок пользователя

### 🤖 ML классификация
- **Автоматическая классификация**: KNeighborsClassifier с 384 признаками
- **145 категорий**: Детальная категоризация заявок
- **Векторизация текста**: sentence-transformers (all-MiniLM-L6-v2)
- **Многоуровневая fallback система**: bot_model → LightGBM → KNN → keywords
- **Админские инструменты**: Управление моделями, статистика, тестирование
- **Обучение на исправлениях**: Система учета пользовательских корректировок

### 👥 Управление доступом
- **Роли пользователей**: admin, specialist, user
- **Ограниченный интерфейс**: Обычные пользователи видят только базовые функции
- **Админские функции**: ML управление, статистика, профили доступны только админам/специалистам

## 🚀 Развертывание

### Продакшн развертывание (рекомендуется)

#### Вариант 1: Со встроенным nginx (по умолчанию)
```bash
# Полное развертывание (БД + бот + nginx)
make deploy

# Или вручную
chmod +x deploy-full.sh
./deploy-full.sh
```

#### Вариант 2: С внешним nginx
```bash
# Развертывание без nginx (только БД + бот)
make deploy-external

# Или вручную
docker-compose -f docker-compose.external-nginx.yml up --build -d
```

При использовании внешнего nginx добавьте конфигурацию:
```bash
# Скопируйте конфигурацию
sudo cp nginx/external-integration.conf /etc/nginx/sites-available/okypbot
sudo ln -s /etc/nginx/sites-available/okypbot /etc/nginx/sites-enabled/

# Перезагрузите nginx
sudo nginx -t && sudo systemctl reload nginx
```

#### Доступные команды
```bash
make help              # Показать все команды
make deploy            # Полное развертывание (с nginx)
make deploy-external   # Развертывание без nginx
make update-bot        # Обновить только бота
make start             # Запустить сервисы
make start-external    # Запустить без nginx
make stop              # Остановить сервисы
make logs              # Просмотр логов
make logs-nginx        # Логи nginx
make status            # Статус сервисов
make backup-db         # Бэкап базы данных
```

## Установка

1. Клонируйте репозиторий:
```bash
git clone <repository-url>
cd okypbot
```

2. Установите зависимости:
```bash
pip install -r requirements.txt
```

**Для ML функций требуются дополнительные зависимости:**
```bash
# Основные ML библиотеки (уже в requirements.txt)
# scikit-learn>=1.4.0
# sentence-transformers>=2.2.0
# numpy>=1.21.0

# Для производительности (опционально)
pip install lightgbm  # Для fallback модели
```

3. Создайте файл `.env` на основе `.env.example`:
```bash
cp .env.example .env
```

4. Заполните переменные окружения в файле `.env`:
   - `BOT_TOKEN` - токен бота от @BotFather
   - `OKDESK_API_TOKEN` - API токен из настроек Okdesk
   - `OKDESK_BASE_URL` - URL вашего аккаунта Okdesk
   - `ADMIN_IDS` - ID администраторов для доступа к ML функциям (через запятую)

## Настройка Okdesk API

1. Войдите в ваш аккаунт Okdesk
2. Перейдите в "Настройки" → "API"
3. Создайте новый API ключ
4. Скопируйте токен в файл `.env`

## 🤖 Настройка ML

Модель `bot_model` уже предварительно обучена и готова к использованию:

- **Модель**: KNeighborsClassifier (145 категорий, 384 признака)

## Настройка Webhooks

Для получения уведомлений о событиях в Okdesk необходимо настроить webhooks:

1. В Okdesk перейдите в "Администрирование" → "Интеграции" → "Webhooks"
2. Создайте новый webhook:
   - **URL**: `https://your-domain.com/okdesk-webhook`
   - **События**: Новый комментарий, Изменение статуса, Назначение исполнителя
3. Настройте подпись для безопасности (опционально)

Подробная документация: [docs/webhook_integration.md](docs/webhook_integration.md)

## Регистрация пользователей

Бот поддерживает два типа пользователей:

### 👤 Физические лица
Требуемые данные:
- ФИО (Фамилия Имя Отчество)  
- Номер телефона

### 🏢 Юридические лица  
Требуемые данные:
- ФИО (Фамилия Имя Отчество)
- Номер телефона
- Должность в компании
- ИНН компании (10 или 12 цифр)

### Процесс регистрации

1. Пользователь выбирает тип (физ./юр. лицо)
2. Вводит ФИО с автоматическим форматированием
3. Указывает номер телефона с валидацией
4. Для юр. лиц: должность и ИНН компании
5. Подтверждает данные
6. Система создает контакт в Okdesk
7. Для юр. лиц: ищет/создает компанию по ИНН
8. Показывается инструкция по работе с ботом

### Валидация данных

- **Телефон**: поддержка форматов +7, 8, 7 + 10 цифр
- **ИНН**: 10 или 12 цифр с проверкой контрольной суммы
- **ФИО**: минимум 2 слова, только буквы и допустимые символы

## API методы Okdesk

Бот использует следующие методы Okdesk API:

### Заявки
- `GET /api/v1/issues` - получение списка заявок
- `POST /api/v1/issues` - создание заявки
- `GET /api/v1/issues/{id}` - информация о заявке
- `PATCH /api/v1/issues/{id}/status` - смена статуса
- `POST /api/v1/issues/{id}/comments` - добавление комментария

### Компании
- `GET /api/v1/companies` - список компаний
- `GET /api/v1/companies/search` - поиск компаний
- `POST /api/v1/companies` - создание компании

### Контакты
- `GET /api/v1/contacts` - список контактов
- `GET /api/v1/contacts/search` - поиск контактов
- `POST /api/v1/contacts` - создание контакта

### Справочники
- `GET /api/v1/issue_types` - типы заявок
- `GET /api/v1/issue_priorities` - приоритеты заявок
- `GET /api/v1/issue_statuses` - статусы заявок
- `GET /api/v1/employees` - сотрудники
