# Исправление проблемы с потерей данных при пересборке Docker контейнеров

## Решение для продакшена

Основная проблема заключается в том, что при пересборке Docker контейнера теряются файлы с данными пользователей, хранящиеся внутри контейнера. Для решения этой проблемы создан скрипт `deploy_to_production.sh`, который выполняет следующие шаги:

1. Создает резервную копию данных из текущего контейнера
2. Останавливает и удаляет контейнеры
3. Обновляет код из репозитория
4. Пересобирает контейнеры
5. Запускает новые контейнеры
6. Восстанавливает данные из резервной копии
7. Исправляет права доступа на файлы

## Как использовать в продакшене

```bash
# 1. Скопируйте скрипт на сервер
scp deploy_to_production.sh user@your-server:/path/to/okypbot/

# 2. Подключитесь к серверу
ssh user@your-server

# 3. Добавьте права на выполнение
cd /path/to/okypbot/
chmod +x deploy_to_production.sh

# 4. Запустите скрипт
./deploy_to_production.sh
```

## Проверка результата

После выполнения скрипта убедитесь, что:

1. Контейнеры запущены:
```bash
docker ps | grep okypbot
```

2. Данные пользователей сохранены:
```bash
docker exec -it okypbot_app ls -la /app/database/
```

3. Проверьте логи на ошибки:
```bash
docker logs okypbot_app
```

## Для решения проблемы долгосрочно

Для постоянного решения проблемы с сохранением данных вы можете внести следующие изменения в `docker-compose.prod.yml`:

```yaml
services:
  bot:
    volumes:
      - ../database:/app/database
```

Это создаст постоянное подключение директории `database` из хост-системы к контейнеру, и данные будут сохраняться даже при пересборке контейнеров.

## Важные замечания

1. Перед внедрением в продакшен всегда делайте полную резервную копию данных.
2. Скрипт создает резервные копии только файлов JSON в директории database.
3. После успешного обновления убедитесь, что бот работает корректно.
