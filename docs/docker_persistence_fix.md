# Исправление проблемы с потерей данных при пересборке Docker контейнеров

## Проблема

При пересборке Docker контейнеров теряются все данные регистрации пользователей, и пользователям приходится регистрироваться заново. Это происходит из-за неправильной конфигурации томов (volumes) в Docker и путей к файлам данных в приложении.

## Причины проблемы

1. **Несоответствие путей**: 
   - В коде используются пути вида `database/users.json`
   - В Docker контейнере данные монтируются в `/app/database`
   - Файлы сохраняются внутри контейнера, а не в постоянные тома

2. **Отсутствие резервного копирования**:
   - Нет механизма сохранения данных перед пересборкой контейнера
   - Данные не восстанавливаются после запуска нового контейнера

3. **Неправильные права доступа**:
   - Возможны проблемы с правами на запись в директории с данными

## Решение

Для решения проблемы были созданы следующие инструменты:

### 1. Скрипты для развертывания с сохранением данных

Созданы два скрипта для разных платформ:
- `scripts/deploy_with_data_persistence.sh` - для Linux/macOS
- `scripts/deploy_with_data_persistence.ps1` - для Windows

Эти скрипты автоматически:
1. Создают резервную копию данных перед остановкой контейнера
2. Останавливают и удаляют старые контейнеры
3. Собирают новые образы
4. Запускают новые контейнеры
5. Восстанавливают данные из резервной копии
6. Исправляют права доступа к файлам

### 2. Скрипт для исправления структуры данных

Создан скрипт `scripts/fix_data_persistence.py`, который:
1. Проверяет и создает необходимые директории
2. Проверяет настройки томов в docker-compose.prod.yml
3. Создает файлы данных с дефолтными значениями, если они не существуют

### 3. Новая система сопоставлений сотрудников

1. Создан обработчик команд Telegram-бота для управления сопоставлениями
2. Создан CLI-инструмент для управления сопоставлениями
3. Добавлена документация по работе с сопоставлениями

## Использование

### Для развертывания обновлений на продакшн-сервере:

#### В Linux/macOS:
```bash
# Добавляем права на исполнение
chmod +x scripts/deploy_with_data_persistence.sh

# Запускаем скрипт развертывания
./scripts/deploy_with_data_persistence.sh
```

#### В Windows:
```powershell
# Запускаем скрипт развертывания
.\scripts\deploy_with_data_persistence.ps1
```

### Для проверки и исправления структуры данных:

```bash
# Linux/macOS
python3 -m scripts.fix_data_persistence

# Windows
python -m scripts.fix_data_persistence
```

### Для настройки сопоставлений сотрудников:

В Telegram боте (для администраторов):
```
/employee_mapping
```

Через командную строку:
```bash
# Показать список сопоставлений
python -m scripts.employee_mapping list

# Интерактивное меню
python -m scripts.employee_mapping menu

# Добавить сопоставление
python -m scripts.employee_mapping add <okdesk_id> <telegram_id>
```

## Рекомендации по продакшен серверу

1. **Всегда используйте скрипты для развертывания**, а не запускайте docker-compose вручную
2. **Регулярно создавайте резервные копии** директории `database_backup`
3. **Проверяйте логи контейнеров** после развертывания:
   ```bash
   docker logs okypbot_app
   ```
4. При каждом обновлении проверяйте структуру данных:
   ```bash
   python -m scripts.fix_data_persistence
   ```

## Дополнительные меры безопасности

1. Настройте cron-задачу для автоматического резервного копирования:
   ```
   0 */6 * * * docker cp okypbot_app:/app/database /backup/okypbot_$(date +\%Y\%m\%d_\%H\%M)
   ```

2. Настройте постоянное хранилище для Docker томов в безопасном месте
